# Databricks FinanceBench Hackathon

## Overview

This repository offers complete examples of implementing GenAI document research agents on Databricks for the [FinanceBench](https://github.com/patronus-ai/financebench). It leverages the Databricks Agent Framework, integrates with [Langchain/Langgraph](https://blog.langchain.dev/langgraph-multi-agent-workflows/), and supports Vector Search, and Unity Catalog Functions. The agents are deployed using Databricks Model Serving and are monitored through Databricks Model Monitoring. 


## Project Structure

This project is brokend down into 6 distict learning modules to assist in the delivery of the FinanceBench Hackathon. Each module is standalone and has its own config files for modularity, but users can choose to centralize the configs as necessary for their own development work.
* `00_smoke_test` contains a set of notebooks for quickly testing your workspace configuration to ensure that features are enabled to run the rest of this repo. It will create a test vector search index and deploy a test endpoint using the agent framework. To run it, follow the instructions below:
  1. Update `smoke_test_config.yaml` with the correct values corresponding to your workspace
  2. Run all cells in the `00_runner` notebook
* `01_vector_search_intro` covers the basics of vector search using mock data that is generated by the `smoke_test`. Users may swap out the vector search index as needed in the `vs_intro.yaml` file
* `02_document_ingestion_enrichment` contains notebooks and a separate configuration YAML to ingest the FinanceBench PDFs (10ks, 10qs, etc.) in the `setup/data` directory
  * This directory contains notebooks to load the financebench pdfs to a volume, parse the pdfs, extract metadata, clean up the chunks, and create the vector search index
  * `__runner` can be used to execute all the notebooks in sequence
* `03_agent_framework` covers the basics of the Agent Framework, LangGraph, and MLFlow Evaluate
  * `03_agent_framework/00_ingest_eval_questions` loads the 150 financebench eval questions to a delta table for downstream evaluation.
  * `03_agent_framework/01_document_agent` defines LangGraph code for a simple document retrieval agent, wrapped in the MLFlow ChatAgent class.
  * `03_agent_framework/02_driver_notebook` contains code for evaluation and deployment of the document agent.
  * `03_agent_framework/retrieval_evaluation` contains code for sweeping vector search indices and configurations to optimize retrieval
* `04_research_agents` implements a deep research architecture using LangGraph to answer sophistcated, multi-turn document Q&A questions
* `05_agent_state` provides and example of how to integrate [Lakebase](https://docs.databricks.com/aws/en/oltp/) to provide long and short term agentic memory.


## Agent Development Workflow
For all agents implemented using the Mosaic Agent Framework, we recommend the following dev workflow:
* `agent_config.yaml` should be updated with your models, catalog, schema, etc.
* `01_agent` contains the core code for the multi-agent supervisor code can be modified to meet customer needs or improve benchmark performance further. The code modifications should be tested using the driver notebook
* `02_driver notebook` executes the code in `01_agent`, tests the agent on example questions, performs the full evaluation, and register/deploys the model.


## Cluster Configs

On Databricks, use either a serverless cluster or a standard cluster running Runtime ML 16.4 LTS or higher.

If you’re using a standard Databricks Runtime, please [install](https://docs.databricks.com/aws/en/libraries/cluster-libraries) the required libraries listed in the [requirements.txt](requirements.txt) file. In this case, you can omit the `pip install ...` commands at the beginning of the notebooks.

If you’re using Serverless compute, please uncomment and run the `pip install ...` commands in each notebook to install the necessary libraries.
